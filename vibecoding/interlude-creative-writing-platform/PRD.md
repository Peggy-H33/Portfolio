# 幕间（Interlude）产品需求文档

> 版本：V0.2 / 作品库与阅读原型版<br>
> 产品定位：让作者笔下的角色，在文字之外继续生活。<br>
> 当前阶段：验证“角色对话 + 可控记忆 + 可解释 Skill”能否形成创作者持续使用的核心体验。

## 1. 产品概述

### 1.1 背景

小说作者在写作时，不只是在安排情节，也在长期维护一群有性格、有关系、有共同经历的人。传统对话产品通常把角色压缩成一段 Prompt：角色能说话，却不真正“活在”一个持续演化的世界里；它们容易串知识、忘记关系、擅自添加正典，作者也很难理解和修改背后的原因。

“幕间”是一个完全服务创作者的 Web 产品。作者可以输入小说、同人设定、人设卡或零散脑洞，由编剧 Agent 辅助创建角色 Agent。角色拥有可编辑的人设、Prompt、行为 Skill 和自己的 Memory；作者可以与一个角色单聊，也能把多个角色拉进群聊，观察他们按各自的人设与所知信息自然互动。

对话中衍生出的生活细节不会直接污染原作。系统将其提取为“候选记忆”，由作者修改、确认后才进入作品正典。

### 1.2 一句话定位

一个让小说创作者创建、管理并观察角色 Agent 持续生活的“角色剧场”。

### 1.3 核心价值

- 角色活起来：角色之间会主动回应、插话、延续关系，而非轮流回答作者。
- 世界不串台：每个角色只依据自己可知的事实回答，允许秘密、误解和信息差存在。
- 作者有最终权：系统只能提议，不能擅自写入正典；Memory、Skill 和 Prompt 都可查、可改、可回滚。
- 创作有回流：群聊产生的新细节能沉淀为可继续写作的材料，而不是一次性聊天记录。

### 1.4 当前产品边界

本阶段是创作者工具，不建设面向普通读者的发布、订阅、评论或社区功能。“读者视角”仅供作者预览某一章节进度下的信息揭示效果。

## 2. 目标用户与场景

### 2.1 目标用户

1. 原创小说作者：维护长篇世界观、人物关系和多条时间线。
2. 同人/二创作者：基于已有背景创建新的关系分支和日常片段。
3. 互动叙事创作者：希望快速试演场景、对白和角色冲突。

### 2.2 核心使用场景

- 作者粘贴一段作品，让编剧 Agent 提取角色、关系、世界事实并生成角色草稿。
- 作者单独与 A 聊天，检查 A 的声音和对事件的理解是否正确。
- 作者把 A、B 拉进群，提出一个问题后观察角色互相接话。
- 群聊衍生出一个有趣生活细节，作者修改后收录为当前分支的正典。
- 作者发现 B 的回应不符合人设，进入 Skill 面板修改行为规则并试演。
- 作者切换到 A、B 或读者视角，检查秘密、误解和伏笔是否越界。
- 作者从作品书架进入某个故事世界，阅读当前全部正文，或选择 AI 自动切分的场景预演人物对白。

## 3. 产品原则

1. **正典必须经作者确认。** AI 生成内容默认为候选，任何“永久记住”都需要作者主动操作。
2. **先让作者看懂，再展示技术原文。** Skill 默认呈现为行为卡，Prompt 原文放在高级视图。
3. **事实与认知分离。** 一次事件只有一条客观事实，但不同角色可有不同理解、遗漏或误解。
4. **角色发言必须可追溯。** 重要回答应能解释使用了哪些 Memory、Skill 和世界事实。
5. **分支之间默认隔离。** 实验剧情不能自动污染正文线。
6. **冲突先停下，不要偷偷圆。** 新信息与锁定正典冲突时，系统向作者提出选择。

## 4. 核心概念

| 概念 | 定义 |
|---|---|
| 作品 Project | 一个独立创作空间，如《雾港来信》 |
| 世界书 World Bible | 地理、时代、规则、地点等相对稳定的客观设定 |
| 时间线/分支 Branch | 正文线或从某个节点分叉的实验剧情 |
| 角色 Character | 由档案、Prompt、Skill、Memory、关系与声音配置共同组成的 Agent |
| 编剧 Agent | 帮作者解析文本、起草角色、发现冲突、提取候选记忆的主 Agent |
| 对话房间 Room | 单聊、群聊或只观察的角色互动空间 |
| Memory | 发生过的事实，以及各视角对它的知情程度和主观理解 |
| Skill | 在特定场景下约束角色行为、语言和关系反应的可编辑规则 |
| Prompt | 角色身份、叙事边界、绝对原则和运行约束的高级描述 |
| 正典 Canon | 经作者确认、在指定分支生效的事实 |

## 5. 信息架构

作者先进入全屏作品库。书架中的每部作品是独立入口，选择后进入该作品的工作台。当前原型中《雾港来信》已经拥有完整工作台，其余五部作品处于构想阶段，进入后会从各自独立的编剧室开始，不会读取《雾港来信》的角色、记忆或对话。

进入作品后，左侧固定导航：

1. **对话现场**：单聊、群聊、观察模式与导演台。
2. **阅读**：阅读当前全部正文，查看 AI 分场结果并预演角色对白。
3. **编剧室**：输入文章/脑洞，提取并创建角色和设定。
4. **角色档案**：人物档案、Skill、Prompt、Memory、声音和版本。
5. **记忆中枢**：故事星图、角色空间、记忆台账和认知矩阵。
6. **世界书**：世界事实、地点、时间线和分支。

全局顶部始终保留：

- 当前作品与功能位置；
- 当前时间线；
- 作者预览视角：全知 / 某角色 / 读者（读至某章）。

## 6. 关键用户流程

### 6.1 从一段文字创建角色

1. 作者在编剧室粘贴小说片段、人设或脑洞。
2. 编剧 Agent 提取角色、关系、世界事实、潜在冲突和待确认问题。
3. 作者逐项勾选、修改或否决。
4. 系统为每个角色生成档案、初始 Prompt、行为 Skill 和种子 Memory。
5. 作者预览角色后，创建单聊或群聊房间。

要求：生成结果始终是草稿；原文来源必须保留；不能把模型推测伪装成作者原设。

### 6.2 群聊让角色互相回应

1. 作者创建房间，选择角色、场景和时间线。
2. 作者用 `@角色` 提问，或投放一句旁白/情节。
3. 导演 Agent 决定谁先回应、谁可以插话、最多自动接话几轮。
4. 每个角色仅能读取本角色可知 Memory、当前世界事实和启用 Skill。
5. 角色完成多轮互相回应；作者可插话、停止、只观察或从某条消息重演。
6. 编剧 Agent 提取衍生事实，显示为候选记忆。

核心示例：

> 作者：@沈砚 今天有没有跟林栀吵架？<br>
> 沈砚：没有。她只是觉得我把纪念日忘了。<br>
> 林栀：哪有，明明是用了一杯桂花乌龙才把我哄好的。<br>
> 沈砚：我错了嘛，不是说喝完就翻篇了吗？<br>
> 林栀：我说的是“再考虑”。

### 6.3 候选记忆进入正典

1. 对话结束后，右侧导演台提示“发现 1 条衍生事实”。
2. 作者点击“查看并收录”，进入 Memory 编辑器。
3. 作者编辑客观事实、状态、类型、时间线、地点、相关角色和来源。
4. 作者在认知矩阵中分别编辑全知事实、林栀认知、沈砚认知、读者揭示进度。
5. 作者选择“收录为正典”“仅保留当前分支”或“丢弃”。
6. 收录后，故事星图和相关角色的 Memory 数量更新；后续对话可使用该信息。

### 6.4 修改 Skill 并试演

1. 作者在角色档案选择一个行为 Skill。
2. 默认看到作用、触发条件、行为规则、禁止事项、优先级和启用状态。
3. 作者直接编辑，或用自然语言让编剧 Agent 起草修改。
4. AI 修改先展示 diff，不直接覆盖。
5. 作者输入一个场景“试演一句”，验证声音是否正确。
6. 保存为新版本；旧版本可回滚。

### 6.5 从作品库进入故事世界

1. 作者打开产品，首先看到黑色全屏作品库。
2. 每部作品以一本可抽出的书呈现，悬停、键盘聚焦或触摸选择时有明确反馈。
3. 作者选择作品后进入对应工作台，作品之间的角色、Memory、Skill 和对话数据必须隔离。
4. 在工作台的作品卡或移动端顶部按钮可随时返回作品库。
5. 返回书架后保留上次进入的作品提示，但刷新仍从作品库开始。

### 6.6 阅读正文与场景预演

1. 作者进入“阅读”，默认看到当前已经导入的全部小说正文。
2. 编剧 Agent 按章节、地点、时间与对白连续性自动切分场景，并标注原文范围和置信度。
3. 作者可从场景目录定位正文，也可点击“预演这一场”。
4. 预演模式使用场景背景呈现台词，角色对白按顺序浮现，并保留前文上下文。
5. 作者可以播放、暂停、回到上一句、前往下一句，以及切换上一场或下一场。
6. 预演不会写入群聊或 Memory，只有作者确认的衍生内容才能进入候选记忆。

## 7. 功能需求

### 7.1 编剧室

#### P0

- 支持粘贴纯文本，后续支持上传 TXT、Markdown、DOCX。
- 提取角色、别名、关系、世界事实、事件和来源位置。
- 标记“原文明确”与“AI 推测”。
- 生成可修改的角色档案、初始 Skill、Prompt、Memory 草稿。
- 遇到歧义时生成待确认问题，不擅自补全。

#### P1

- 增量导入新章节，只更新受影响内容。
- 展示与已有正典的冲突与合并建议。
- 提供“按我的写作风格重写行为示例”。

### 7.2 角色档案

每个角色包含：

- 基础：姓名、别名、头像、角色职责、年龄等；
- 内核：欲望、恐惧、价值观、底线、矛盾点；
- 语言：节奏、词汇、口头习惯、禁用表达；
- 关系：与其他角色的关系状态和例外规则；
- Skill、Prompt、Memory、声音与版本；
- 每个字段的来源与最近修改人。

要求：角色更新默认创建草稿版本；发布后才影响新对话；历史消息不追溯重写。

### 7.3 Skill 系统

作者视图字段：

- Skill 名称与作用；
- 触发条件；
- 行为规则；
- 禁止事项；
- 适用关系、场景和时间线；
- 正例/反例台词；
- 优先级与启用状态；
- 来源、版本和变更说明。

运行规则：

- 仅注入当前场景匹配的 Skill；
- 高优先级底线不能被低优先级风格覆盖；
- Skill 冲突时导演 Agent 停止自动接话并提示作者；
- Skill 不能授予角色其 Memory 中不存在的知识。

### 7.4 Prompt 系统

- 普通作者默认不需要阅读代码式 Prompt。
- 高级视图展示核心身份、世界边界、叙事约束和编译后的运行 Prompt。
- 编辑支持自然语言建议和结构化字段，两者都先生成 diff。
- 发布、回滚、复制为分支版本。

### 7.5 Memory 系统

#### 记忆数据

- 标题、客观事实摘要；
- 状态：正典 / 候选 / 临时 / 废弃；
- 类型：世界事实 / 角色记忆 / 关系记忆 / 共同经历 / 秘密 / 剧情种子；
- 所属作品、分支、时间、地点；
- 相关角色；
- 来源与原文定位；
- 锁定状态与版本历史；
- 每个视角的知情程度、主观理解与可信度。

#### 三类视角

1. **全知视角（作者看）**：客观事实、幕后原因、所有秘密和冲突。
2. **角色视角**：每个角色只看到亲历、被告知或推断的内容；允许误解和不可靠记忆。
3. **读者视角**：作者用来检查截至某章节已经揭示的信息；不是读者账户体系。

#### 故事星图

- 中心显示作品正典与待确认数量；
- 周围显示角色节点及其 Memory/Skill 数量；
- 点击角色进入角色空间；
- 实线表示共同知情，虚线表示部分知情，冲突/误解应有独立标记；
- 星图负责理解关系，台账负责高效编辑。

#### 写入策略

- 模型生成内容一律先进入候选区；
- 锁定正典不能被自动改写；
- 修改正典会提示受影响的角色、房间和分支；
- 对话运行时按相关性、时间线、视角和优先级检索，不把全部 Memory 塞进上下文。

### 7.6 对话现场与导演 Agent

房间类型：

- 单聊：作者与一个角色；
- 群聊：作者与多个角色，角色可互相回应；
- 只观察：作者投放场景后暂不发言；
- 重演分支：从某条消息创建实验时间线。

导演控制：

- 在场角色和当前状态；
- 允许主动插话；
- 自动接话轮数；
- 冲突保护等级；
- 角色发言顺序与停止条件；
- 候选记忆提取；
- 标记“不符合人设”并回溯使用的 Skill/Memory。

### 7.7 世界书与时间线

- 管理世界规则、地点、组织、物品、历史事件；
- 支持正文线与多个实验分支；
- 分支继承创建点以前的正典，之后默认隔离；
- 合并分支时显示 Memory、关系和时间冲突；
- 作者可把优秀分支内容挑选合并回正文。

### 7.8 声音

#### P1

- 角色绑定第三方语音模型的 Voice ID；
- 支持上传样本、调整音色、语速、情绪范围和禁区；
- 单句试播和群聊自动播报；
- 明确展示授权和克隆声音风险；禁止使用未经授权的真实人物声音。

## 8. 核心数据模型（概念）

```text
Project
 ├─ WorldFact[]
 ├─ Branch[]
 ├─ Character[]
 │   ├─ CharacterVersion[]
 │   ├─ SkillVersion[]
 │   └─ VoiceProfile
 ├─ Event[]
 │   └─ PerspectiveMemory[]  # 每个视角对同一事件的认知
 └─ Room[]
     ├─ Message[]
     └─ MemoryCandidate[]
```

建议核心关系：

- `Event` 保存客观发生的事；
- `PerspectiveMemory` 保存某角色知道多少、如何理解、是否误记；
- `MemoryCandidate` 保存模型从对话提取但尚未成为正典的建议；
- 所有实体带 `project_id`、`branch_id`、版本和来源，避免作品/分支串数据。

## 9. MVP 范围

### P0：必须完成

- 创建一个作品并管理时间线；
- 粘贴文本，由编剧 Agent 生成角色草稿；
- 角色档案、Prompt、结构化 Skill 的查看/编辑/版本；
- 单聊和 2 至 4 人群聊；
- `@角色`、角色互相插话、自动接话轮数；
- 对话提取候选记忆；
- Memory 台账、认知矩阵、作者确认进入正典；
- 全知/角色/读者预览视角；
- 分支隔离与基础回滚；
- 对话、Memory、Skill 的来源追踪。

### P1：MVP 后

- 语音捏制和群聊播报；
- 文件批量导入、增量章节解析；
- 关系图、地点图与更复杂的故事星图；
- AI 修改 diff、冲突批处理；
- 多设备同步、导出世界书和角色包。

### 本阶段明确不做

- 读者社区、公开发布、订阅与创作者交易市场；
- 多人协作写作和复杂权限；
- 自动替作者续写整章作为主功能；
- 让 AI 未经确认自动改写正典；
- 真人声音的无授权克隆。

## 10. 体验与非功能要求

### 10.1 可解释性

- 重要发言支持查看“使用了哪些 Memory/Skill”。
- AI 对角色、Memory、Skill 的修改必须有来源和 diff。
- 无来源的模型推断明确标为“AI 提议”。

### 10.2 一致性与安全

- 所有数据按用户、作品、分支隔离。
- 角色不能读取其他角色私有 Memory。
- 锁定正典写入前必须二次确认。
- 提供版本历史、软删除和恢复。

### 10.3 性能目标

- 常规页面交互反馈小于 200ms；
- 第一位角色回复目标小于 4 秒，并展示思考/排队状态；
- 长篇作品采用检索与摘要，不随篇幅线性扩大单次上下文；
- 群聊自动接话可随时停止。

### 10.4 可访问与响应式

- 桌面端优先，核心查看/编辑流程适配 375px 以上移动设备；
- 所有图标按钮有可访问名称；
- 键盘可完成导航、发送和关闭编辑器；
- 状态不能仅用颜色表示。

## 11. 成功指标

### 激活

- 新作者在首次会话中成功创建 ≥2 个角色并进入一次群聊的比例。
- 从导入文本到角色首次开口的中位时间。

### 核心价值

- 每个活跃作品每周完成的群聊场景数。
- 群聊中角色互相回应（非只回复作者）的比例。
- 候选记忆被作者打开、编辑和收录的比例。
- 作者标记“不符合人设”的消息比例及其随使用时间的下降趋势。

### 留存

- 作者次周返回同一作品继续对话或编辑 Memory 的比例。
- 正典 Memory、Skill 版本和活跃时间线的累积情况。

北极星指标建议：**每个周活跃作品中，经作者确认进入正典的“角色生活事件”数量。**

## 12. 风险与应对

| 风险 | 影响 | 应对 |
|---|---|---|
| 角色越聊越不像本人 | 破坏沉浸与信任 | Skill/Prompt 版本、发言追溯、不符合人设反馈、回归试演集 |
| 群聊产生大量低质“假设定” | 正典污染 | 默认候选、批量审阅、来源标记、锁定正典 |
| 角色互相泄露秘密 | 世界观崩坏 | 事实/认知分离、运行时视角检索、越权测试 |
| 长篇记忆成本过高 | 延迟和费用增长 | 事件结构化、分层摘要、向量检索、热/冷记忆 |
| 分支串线 | 不可逆的数据混乱 | Branch ID 强隔离、合并 diff、软删除和快照 |
| 作者不懂 Prompt | 编辑门槛高 | 默认行为卡、自然语言修改、高级视图后置 |
| 声音侵权 | 法律与平台风险 | 授权证明、风险提示、禁止公众人物无授权克隆 |

## 13. MVP 验收标准

满足以下完整闭环，才视为核心 MVP 成立：

1. 作者创建两个角色并进入群聊。
2. 作者 `@A` 后，A 回答、B 主动插话、A 再回应，且各自语气不同。
3. 系统从这段对话提取一条候选记忆，不直接写入正典。
4. 作者能修改客观事实以及 A、B、读者三个视角的理解。
5. 作者确认后，该记忆进入指定分支正典，星图与角色计数更新。
6. 后续与 A/B 对话时，只有知情角色能正确使用该记忆。
7. 作者修改某个 Skill，完成一句试演并保存新版本。
8. 刷新后数据仍存在；恢复演示/版本回滚不会影响其他作品或分支。

## 14. 原型验证说明

本次网页原型重点验证：

```text
进入群聊
→ 看到 A / B 互相接话
→ 打开自动提取的候选记忆
→ 编辑认知矩阵并收录为正典
→ 返回故事星图查看数量变化
→ 打开角色 Skill
→ 修改、试演并保存版本
```

编剧室、世界书和声音功能在原型中用于展示产品边界；真实模型调用、文件解析、账号系统、服务端数据库与语音 API 不包含在本地静态原型范围内。
