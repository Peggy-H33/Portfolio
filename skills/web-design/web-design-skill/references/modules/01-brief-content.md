# 01 — Brief and content architecture

## Goal

Turn an open-ended site request into a factual content model before styling.

## Extract

- Concrete subject and category.
- Primary audience and their prior knowledge.
- One page job: understand, compare, inquire, buy, register, explore, or trust.
- Primary action and lower-commitment secondary action.
- Available facts, claims, quotes, metrics, product imagery, videos, and legal constraints.
- Page length: compact, standard, or narrative long-form.
- Technical context: static HTML, framework, CMS, browser support, localization.

## Produce 3 narrative structures

Do not reuse the same landing-page sequence automatically.

1. Thesis → evidence → mechanism → outcome → action.
2. Context → tension → reveal → exploration → action.
3. Artifact-led: hero artifact → annotated chapters → applications → next step.

Select by page job. Persist section purpose and actual content source.

## Copy rules

- Use concrete nouns and active verbs.
- Make the headline a claim the page can support, not an empty slogan.
- A label labels; an example demonstrates; a button states the result of clicking.
- Keep interface vocabulary stable across navigation, CTA, and confirmation.
- Mark unsupported metrics and superlatives as prohibited until sourced.
- Do not put internal notes, prompt language, template names, “proof,” or design rationale into visible UI.

## Gate

Pass when every planned section has a user-facing purpose and evidence source. Remove any section whose only rationale is “websites usually have this.”
